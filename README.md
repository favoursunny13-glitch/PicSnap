# PicSnap Playable Prototype

Phaser 3 CDN을 사용하는 정적 웹 퍼즐 게임 프로토타입입니다. 별도 빌드나 서버 애플리케이션은 필요하지 않습니다.

졸업 축하 화면의 불꽃놀이는 `js/celebration-fireworks.js`에서 Canvas 2D로 렌더링합니다. 폭죽은 축하 화면이 열린 동안 반복되며, 화면을 닫거나 메인 장면을 종료하면 렌더링을 중단합니다.

퍼즐은 화면 중앙의 고정된 3×3 보드 안에서 9개 조각의 시작 위치를 무작위로 섞어 생성합니다. 조각을 다른 칸으로 옮기면 해당 칸에 자동 정렬되고, 기존 조각과 위치가 교환됩니다.
연결되지 않은 조각은 둥근 모서리와 칸 사이 여백으로 구분됩니다. 정답 위치에서 서로 맞닿은 조각이 2개 이상이면 연결된 조각으로 표시되어 여백 없이 원본 이미지처럼 이어집니다.
스테이지 최초 셔플에서는 서로 맞는 조각이 우연히 연결되지 않습니다. 한 번 연결된 조각 중 하나를 드래그하면 연결 그룹 전체가 함께 이동하며, 놓은 위치의 칸에 그룹 단위로 자동 정렬됩니다.
클리어 표시는 현재 페이지를 사용하는 동안만 유지되며, 브라우저를 새로고침하면 모두 초기화됩니다.
스테이지 선택 화면의 미리보기는 클리어 전까지 약한 블러 효과로 표시됩니다. 스테이지를 클리어하면 해당 미리보기와 완료 화면에서 블러 없는 원본 이미지가 공개됩니다.
패션 사진의 디테일을 보존하기 위해 퍼즐 조각은 고정 저해상도로 축소하지 않고 원본 셀 해상도를 사용합니다. 이미지 스케일링에는 고품질 보간을 적용하며, 고해상도 화면에서는 성능을 고려해 최대 3배 HiDPI로 렌더링합니다.
텍스트는 모니터의 실제 전체 화면 해상도에 맞춰 최소 2배, 최대 3배 해상도의 전용 텍스처로 렌더링합니다. 4K 전체 화면에서도 글자가 확대 보간되지 않도록 캔버스 해상도를 자동 선택하며, 캔버스 전체 CSS 필터는 사용하지 않습니다.
스테이지 클리어 화면에서는 완성 이미지를 크게 표시합니다. 이미지 위에 커서를 올렸을 때는 그대로 보이며, 이미지를 누르는 순간에만 시스템 마우스 커서를 숨깁니다. 포인터 위치를 중심으로 원본이 0.2초에 걸쳐 2배까지 확대되고, 포인터를 놓으면 커서가 즉시 복원되면서 0.2초 동안 기본 배율로 부드럽게 축소됩니다.
각 스테이지에 진입하는 순간부터 클리어까지의 시간이 `분:초:밀리초` 형식으로 퍼즐 보드 위에 표시됩니다. 클리어 후 원본 이미지를 먼저 감상한 다음 `SAVE MY RECORD`를 선택하면 닉네임을 입력하고 해당 스테이지 랭킹을 확인할 수 있습니다. 메인 화면 우측 상단의 `VIEW RANKING`에서도 스테이지별 기록을 볼 수 있습니다. 현재 정적 GitHub Pages 버전의 랭킹은 브라우저의 로컬 저장소에 보관되므로 다른 기기나 브라우저와 공유되지 않습니다.
개발자용 랭킹 초기화는 메인 화면의 `VIEW RANKING` 패널이 열려 있을 때 Backquote 키(`)를 다른 키 없이 단독으로 누르면 실행됩니다. `Shift + Backquote(~)`와 `Ctrl`·`Alt`·`Meta` 조합은 무시합니다. 모든 스테이지의 로컬 랭킹이 삭제되고 현재 랭킹 표가 즉시 갱신되며, 실제 게임 화면에는 초기화 버튼이나 단축키 안내를 노출하지 않습니다.
랭킹 패널의 제목·탭·안내문·닉네임·시간은 별도의 최대 6배 고해상도 텍스트 텍스처로 렌더링되며, 스테이지 탭을 전환해 새 텍스트가 생성될 때도 같은 선명도 설정을 다시 적용합니다.
닉네임 입력 창이 열려 있는 동안에는 뒤쪽 게임 캔버스의 입력을 잠급니다. 창 바깥을 클릭하거나 모달의 버튼을 조작해도 완성 이미지의 확대 기능이 실행되지 않으며, 모달이 닫힌 다음 프레임에만 게임 입력이 복원됩니다.
좌우 원형 레일과 세로 타이포는 고정 16:9 캔버스가 아닌 전체 브라우저 화면의 반응형 장식 레이어에서 렌더링됩니다. 16:9에서는 원형에 가까운 비율을 유지하고, 울트라와이드에서는 여백 크기만큼 가로로 확장된 타원이 되어 선이 캔버스 경계에서 잘리지 않습니다. 세로형 화면에서는 게임 화면 높이에 맞춰 함께 축소되며 중앙 콘텐츠 영역으로 갈수록 투명하게 사라집니다. 페이지 진입 시 좌우 레일과 타이포가 순차적으로 활성화되고 장식 레이어는 포인터 입력을 받지 않습니다.
전체 UI는 블랙·일렉트릭 바이올렛·소프트 라벤더를 중심으로 한 프리미엄 패션 에디토리얼 스타일을 사용합니다. 글래스 패널, 앰비언트 글로우, 카드 시머·호버 모션, 연결 펄스, 클리어 리빌 플래시와 파티클 효과가 포함됩니다.
울트라와이드 및 다양한 모니터 비율에서는 16:9 게임 화면을 왜곡하지 않고, 남는 좌우 공간을 반응형 글로우·사이드 레일·메탈 엣지 프레임으로 자연스럽게 확장합니다.

## 실행

브라우저의 로컬 파일 제한을 피하려면 `D:\PicSnap`에서 정적 웹 서버를 실행한 뒤 접속하세요.

```powershell
python -m http.server 8000
```

그다음 `http://localhost:8000`을 엽니다.

## 실제 이미지 추가

메인 화면은 Stage 01–03을 가로 한 줄에 표시합니다. 각 스테이지는 `assets/images/stage01.jpg`, `stage02.jpg`, `stage03.jpg` 원본을 사용합니다. 파일을 직접 열면 Phaser가 Canvas 렌더러에서 JPG를 직접 로드합니다.

이미지를 바꿀 때는 JPG를 교체하고 `js/game.js`의 `STAGES`에 있는 해당 이미지 URL의 버전을 갱신합니다.

이미지는 원본 가로세로 비율을 유지한 채 전체 영역이 3×3 조각으로 분할됩니다. 퍼즐 보드 테두리와 각 칸 크기도 이미지 비율에 맞춰 자동으로 변경됩니다.

## 사진 방명록

메인 화면의 `VIEW RANKING` 왼쪽 `방명록 남기기` 버튼에서 사진 방명록으로 이동합니다.
카메라 시작 → 양손의 엄지·검지 집기 → 3초 후 촬영 → 촬영 사진이 표시된 팝업에서 이름 입력 → 방명록 저장 순서입니다. 팝업에서 다시 촬영할 수 있으며, 닫아도 촬영 사진과 입력한 이름을 유지해 `촬영한 사진 확인 · 이름 남기기`로 다시 열 수 있습니다.
촬영 기능은 `Puzzle-main`의 손가락 프레임 캡처를 분리한 것으로, 방명록에는 퍼즐이 없습니다. 기존 PicSnap 게임과 랭킹은 유지됩니다.
선택한 필터가 적용된 사진과 이름(1~30자), 실제 촬영 시각을 저장합니다. 한국 시간으로 표시하며 이름·날짜 검색, 더 보기, 사진 확대를 지원합니다.
확대된 촬영 화면 하단과 촬영 후 이름 입력 팝업에서 `기본`(컬러), `흑백`, `글리치` 필터를 선택할 수 있습니다. 선택 즉시 미리보기에 반영되고, 다시 촬영할 때도 선택을 유지합니다. 처음에는 `기본`이 선택됩니다.
`사진 업로드`는 20MB 이하의 브라우저에서 읽을 수 있는 이미지를 지원합니다(JPG/PNG/WebP 권장). 업로드 사진은 불러온 시각을 기록합니다. 촬영·업로드 모두 비율을 유지하며 긴 변 최대 1280px의 JPEG로 저장합니다.
글리치는 `js/guestbook-portrait.js`에서 얼굴 위치만 분석하고, `js/guestbook-filters.js`에서 얼굴 높이를 기준으로 이미지 전체에 얇은 수평 왜곡과 옅은 RGB 잔상을 적용합니다. 인물 분할·누끼 처리를 하지 않으며 배경에도 동일한 효과를 적용하고 원래 밝기를 유지합니다. 얼굴 모델은 처음 글리치를 선택할 때 다운로드하므로 인터넷 연결이 필요합니다. 분석은 브라우저 안에서 실행됩니다. 지원 환경에서는 Worker를 사용하며 얼굴 인식을 잃으면 효과가 서서히 사라집니다. 사진에서 얼굴을 찾지 못하면 안내와 함께 원본을 표시합니다. 사진별 시드를 유지하고 원본에서 재처리하여 효과가 누적되지 않으며 미리보기 JPEG를 그대로 저장합니다.
사용법은 카메라 시작 버튼 위에 표시됩니다. 각 방명록 카드의 `삭제` 버튼에서 사진·이름·촬영 시각을 확인한 뒤 삭제할 수 있습니다. 삭제 확인 창에서는 취소할 수 있으며, 실패하면 다시 시도할 수 있습니다. 공유 저장 모드에서 삭제하면 공유 서버에서도 기록이 삭제됩니다. 현재 별도의 계정 구분은 없으므로 사이트 이용자는 표시된 방명록을 삭제할 수 있습니다.
`카메라 시작` 또는 `다시 촬영`을 누르면 촬영 프레임이 브라우저 화면을 최대한 채우도록 확대됩니다. 영상 비율을 유지하며, 촬영 완료 후에는 원래 화면으로 돌아와 이름 입력 팝업을 엽니다. 확대 화면의 `촬영 닫기` 또는 Esc로 촬영을 중지할 수 있습니다.
카메라는 촬영 시작 시에만 요청하고, 촬영 완료·페이지 이동·다른 탭 전환 시 해제합니다. HTTPS 또는 localhost가 필요하며 손 인식 모델을 불러올 인터넷 연결도 필요합니다.

방명록 화면에서 F8을 다섯 번 누르면 디버그 모드가 활성화됩니다. 카메라 촬영 없이 작성 창을 열고, 저장하면 이름과 코멘트가 `DEBUG MODE` 이미지와 함께 현재 방명록 저장소에 남습니다. 모드는 페이지를 새로고침하면 해제됩니다.

### 저장 방식

- **기존 GitHub Pages / 정적 서버:** IndexedDB에 사진을 보관합니다. 같은 브라우저에서는 새로고침·재접속 후 볼 수 있지만 다른 기기와 공유되지 않습니다. 사이트 데이터 삭제 시 기록도 삭제됩니다.
- **공유 방명록 서버:** Python 3.10 이상과 Playwright Chromium을 준비한 뒤 실행합니다. Linux 배포 환경에서는 Chromium 시스템 의존성(`python -m playwright install --with-deps chromium`)과 한글 글꼴(예: Noto Sans KR)을 설치하고, Chromium 샌드박스를 사용할 수 있는 일반 사용자 계정에서 서버를 실행합니다.

```sh
python -m pip install -r requirements.txt
python -m playwright install chromium
python server.py --port 8000
```

`http://localhost:8000`에 접속하면 같은 서버를 사용하는 방문자들이 사진과 이름을 함께 볼 수 있습니다. API가 연결되면 공유 저장으로 자동 전환되며, 화면에 저장 범위가 표시됩니다. 공유 서버 오류를 브라우저 저장으로 조용히 대체하지 않습니다.
SQLite 파일은 기본적으로 `.guestbook-data/guestbook.sqlite3`에 저장됩니다. `--database /absolute/path/guestbook.sqlite3` 또는 `PICSNAP_GUESTBOOK_DB` 환경변수로 위치를 지정할 수 있습니다. 방명록을 저장할 때 필터 사진, 이름, 한국 시간 기준 일시와 코멘트를 담은 상세 화면을 `.guestbook-data/archive/<방명록 ID>.png`에 자동으로 보관합니다. DB 경로를 따로 지정하면 기본 보관 폴더는 그 DB 옆의 `archive`입니다. `--archive-dir` 또는 `PICSNAP_GUESTBOOK_ARCHIVE_DIR`로 보관 폴더를 지정할 수도 있습니다.

기존 SQLite에 남아 있는 기록의 PNG는 서버를 시작할 때 생성합니다. 시작이 중단되어도 다시 실행하면 이미 생성된 파일을 건너뜁니다. 웹에서 삭제하면 공개 목록과 사진 URL에서 기록을 제거하고, 운영자 폴더의 PNG는 유지합니다. 공유 서버는 보관 경로로 들어오는 웹 요청을 차단합니다. 정적 서버로 확인할 때는 실사용 데이터 폴더가 없는 사이트 복사본을 제공하세요.

내 PC에서 `server.py`를 실행하면 PNG가 내 PC에 저장됩니다. 배포할 때는 개인 홈페이지에서 공유 방명록 주소로 연결하고, 같은 HTTPS 출처에서 방명록 페이지와 API를 제공하세요. 기존 기록을 이어 쓰려면 SQLite와 PNG를 함께 서버의 영구 디스크로 옮기고, 각 위치를 설정합니다. 실행 중 DB를 복사할 때는 SQLite backup API를 사용하세요. 웹에서 삭제한 기록의 PNG는 보관 폴더를 복사해야 함께 이전됩니다.

실제 웹사이트에서 여러 기기의 방명록을 공유하려면 Python 서버를 실행할 수 있는 호스팅에 배치하고 HTTPS를 연결해야 합니다. GitHub Pages는 Python 서버를 실행하지 않습니다. 로컬 저장 기록과 공유 서버 기록은 별도로 관리됩니다.

저장 실패 시 촬영 사진과 이름은 유지되어 재시도할 수 있으며, 같은 촬영의 중복 요청은 하나의 기록으로 처리됩니다. 방명록 목록은 카메라 권한 없이 조회할 수 있습니다.

### 파일에서 카메라 실행

`index.html`을 직접 열고 `방명록 남기기` → `카메라 시작`을 누를 수 있도록 방명록의 로컬 스크립트를 일반 스크립트로 로드합니다. 손 인식 라이브러리는 HTTPS에서 불러오므로 인터넷 연결이 필요합니다. 파일 실행에서는 공유 API를 요청하지 않고 IndexedDB를 사용합니다. 브라우저가 파일 출처의 카메라나 저장소를 제한하면 `http://localhost:8000/index.html`로 접속해야 합니다.

카메라 권한 요청은 최대 45초, 영상 재생은 최대 15초까지 기다린 후 실패 이유를 표시합니다. 권한은 브라우저의 사이트 설정과 macOS의 시스템 설정 → 개인정보 보호 및 보안 → 카메라에서 허용해야 합니다. 손 인식 모델을 불러오는 동안에도 실시간 미리보기를 표시합니다.

### 방명록 코멘트

촬영 또는 업로드 후 이름 아래에 코멘트를 선택 입력할 수 있습니다(최대 500자, 줄바꿈 지원). 글자 수가 표시되며 코멘트 없이도 저장할 수 있습니다. 목록에서는 최대 세 줄을 미리 보고, 사진을 누르면 전체 코멘트를 확인할 수 있습니다. 입력 창을 닫거나 저장에 실패해도 작성한 내용이 유지되며, 저장 완료 또는 촬영 취소 시 초기화됩니다.
코멘트는 사진·이름과 함께 브라우저 또는 공유 서버에 저장됩니다. 공유 모드에서는 다른 방문자에게도 공개됩니다. 기존 서버는 재시작 시 SQLite에 코멘트 열을 자동 추가하며, 기존 방명록은 빈 코멘트로 표시됩니다.

### 방명록 PNG 이메일 발송

촬영 팝업의 저장 버튼 위에서 이메일을 선택 입력합니다. 공유 서버는 기존 상세 화면 PNG와 수신 주소를 연결한 발송 대기 기록을 SQLite에 보관합니다. 공개 목록, 상세 화면과 PNG에는 이메일 주소를 포함하지 않습니다. 정적/IndexedDB 모드에서는 이메일 입력을 비활성화합니다.

`guestbook_mail.py`는 Gmail SMTP 발송 작업자와 로컬 관리 명령을 담당합니다. `server.py`가 작업자를 시작하고 종료합니다. 같은 데이터베이스에는 서버 하나만 실행합니다. 이메일 연결 전에도 방명록과 대기 기록을 저장하며, 다음 환경변수를 설정한 뒤 서버를 재시작하면 기존 대기 기록부터 순차 발송합니다.

| 환경변수 | 설정값 |
|---|---|
| `PICSNAP_GMAIL_ADDRESS` | 발신 Gmail 주소 |
| `PICSNAP_GMAIL_APP_PASSWORD` | 계정 주인이 생성한 앱 비밀번호 |

계정 주인이 Google 계정에서 2단계 인증을 켜고 `PicSnap`용 앱 비밀번호를 생성해 서버 실행 환경에 직접 설정합니다. 서버는 `smtp.gmail.com:587`에 STARTTLS로 연결합니다. 비밀번호는 소스, 브라우저 스크립트, Git 또는 채팅에 기록하지 않습니다. 설정을 변경하면 서버를 재시작합니다. 설정 여부는 인증 성공을 보장하지 않으므로 연결 후 테스트용 방명록으로 실제 수신을 확인합니다. [Google 앱 비밀번호 안내](https://support.google.com/mail/answer/185833?hl=ko)

메일 제목은 `방명록 사진을 보내드립니다`, 표시 이름은 `PicSnap`, 첨부 파일명은 `PicSnap.png`입니다. SMTP 접수 완료는 수신함 도착을 보장하지 않습니다. 같은 방명록 ID의 저장 재시도는 수신 주소를 변경하거나 새 발송 작업을 만들지 않습니다. PNG 생성에 실패한 기록은 공개 및 발송을 보류하고 저장 재시도나 서버 재시작으로 복구합니다.

발송은 2초마다 대기 작업을 하나씩 처리합니다. 일시적 SMTP 오류는 1분부터 최대 1시간 간격으로, 연결 오류는 5분 뒤 재시도합니다. 한도 오류를 받으면 새 작업을 포함해 발송을 24시간 보류하며 재시작 후에도 이 시간을 유지합니다. 인증 실패는 작업자를 중지하므로 설정을 고친 뒤 서버를 재시작하고 실패 작업을 재등록합니다.

전송 중 연결이 끊겨 접수 여부가 불명확하거나 처리 중 서버가 종료되면 `unknown`으로 보관합니다. 이 상태를 재시도하면 중복 메일이 갈 수 있으므로 운영자가 확인한 뒤 다음 명령으로 개별 재시도합니다. 명령은 PicSnap 폴더에서 실행하며, 사용자 지정 DB를 사용하면 `--database`에 동일한 경로를 지정합니다.

```sh
python guestbook_mail.py --database /absolute/path/guestbook.sqlite3 list
python guestbook_mail.py --database /absolute/path/guestbook.sqlite3 retry <방명록-ID>
```

목록에는 ID, 상태, 시도 횟수, 다음 시도 시각(Unix 초), 오류 분류가 표시됩니다. 상태는 `pending`(대기), `sending`(전송 중), `accepted`(SMTP 접수), `failed`(실패), `unknown`(결과 확인 필요)입니다. `retry`는 `failed` 또는 `unknown`에만 적용합니다. 웹에서 방명록을 삭제하면 관련 수신 주소와 대기 기록을 제거합니다. 이미 전송을 시작한 메일은 도착할 수 있습니다.

추가 검증은 `python -m unittest discover -s tests -p test_guestbook_mail.py`와 `node tests/guestbook-email.browser.cjs`로 실행합니다. 이메일 테스트는 가짜 SMTP 객체와 테스트용 PNG를 사용합니다. 브라우저 테스트는 API 응답을 모의 처리하여 공유/정적 화면을 검증합니다. 기존 실제 PNG 렌더링 테스트는 Python Playwright와 Chromium 설치가 필요합니다.
